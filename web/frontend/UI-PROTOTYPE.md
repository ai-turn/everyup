# 개요·업타임 정보 구조 비교 시안

이 브랜치는 화면의 정보 목적과 구조를 비교하기 위한 탐색 브랜치다. 개요와 업타임 B/C는 임시 시안으로 보존한다. 사용자가 선택한 업타임의 기본 그리드·카드 전환은 기존 추가/일시정지/상세 복귀 기능을 유지하는 실제 컴포넌트로 구현했다.

## 실행

`web/frontend`에서 `pnpm dev:ui-prototype`을 실행한다. 기존 데모 데이터를 사용하며 서버나 계정은 필요 없다.

- 개요: <http://127.0.0.1:5186/?variant=A>
- 업타임 목록: <http://127.0.0.1:5186/uptime> — 기본 그리드, 상단에서 카드 전환. `view=card`로 직접 열 수 있다.
- 하단 비교 바의 화살표 또는 키보드 좌우로 `current → A → B → C`를 전환한다. 입력창에서는 방향키로 시안을 바꾸지 않는다.
- URL의 `variant` 값은 새로고침 후에도 유지된다. 비교 바에서 개요와 업타임을 오갈 수 있다.
- 데모 시나리오 메뉴로 정상·장애 등 데이터 상황을 바꿀 수 있다. 시안은 기존 조회 흐름을 공유한다.

## 비교하는 질문

현재 카드나 배치를 유지할 이유부터 다시 검토한다. 어떤 화면이 많은 데이터를 넣는가보다, 사용자가 어떤 정보를 비교하고 무엇을 다음에 조사하는지 확인한다.

| 안 | 개요의 중심 | 업타임 목록의 중심 |
|---|---|---|
| current | 기존 배포 개요 | 선택한 그리드·카드 목록 |
| A | 환경 안의 서비스 이름과 상태를 펼친 상태판 | 선택한 그리드·카드 목록 |
| B | 환경별 수신·서비스 상태의 범위 비교 | 대상 목록과 선택한 대상의 빠른 확인 패널 |
| C | 장애 시간 구간과 선택한 기록 | 환경·직접 체크별 접을 수 있는 그룹 |

## 현재 추천과 한계

- **개요의 목적을 서비스·환경별 전체 상태로 수정했다.** 사용자 피드백에 따라 A를 조사 목록에서 환경별 상태판으로 교체했다. 정상 서비스도 이름과 상태를 직접 볼 수 있고 Collector 수신은 별도로 표시한다. 직접 모니터와 Telemetry/인프라 수집도 구분한다. 최근 장애 이력은 접을 수 있는 보조 기록으로 내렸다.
- **업타임은 기본 그리드+카드 전환으로 선택했다.** 그리드와 카드는 같은 데이터·검색·상태 순서를 사용한다. 선택은 URL에 보존되어 새로고침과 상세 복귀 시 유지된다. 카드 보기에서도 기존 일시정지/재개를 제공한다.
- 375px 그리드는 주소와 마지막 확인을 대상 열에 모아서 가로 이동 없이 읽을 수 있게 했다. 상태 변경은44px 버튼으로 유지한다. 큰 상태 요약 카드를 작은 상태 행으로 바꿔 목록이 아래로 밀리는 비용을 줄였다.
- 이전 첫 비교에서의 대상 수·장애 노출 측정은17353bd4의 과거 시안에 대한 결과다. 현재 구조의 우월성이나 사람의 탐지 속도를 입증하는 수치로 재사용하지 않는다.
- B의 빠른 확인 패널은 모바일에서 목록 아래에 놓이는 비용이 남는다. C는 환경 단위로 조사할 때 유용하다.
- C의 그룹 순서는 출처 순서다. 다른 환경의 장애를 찾으려면 스크롤이 필요하며 헤더는 정상/장애 수만 요약한다. 접힌 상태의 수집 지연·대기·정지 표현은 후속 설계 항목이다.
- 개요 C는 최근 7일 중 최신 6개 기록만 사용한다. 빈 구간의 정상 여부나 전체 장애 건수를 뜻하지 않는다. 짧은 장애는 긴 시간축에서 매우 작아진다.
- Collector 수신 상태와 서비스 가용성을 구분한다. 목록에 없는 과거 추이·장애 시작·영향도·SLO를 만들어 표시하지 않는다.

## 검증 범위

첫 비교는88개 화면을 관찰했다. 사용자 피드백을 반영한 이번 반복에서는 선택한 업타임 보기와 기존 동작에 대한36개 E2E, 새 개요의20개 상태/폭 조합, 실제 데모의12개 light/dark 캡처를 확인했다. 개요는 정상·장애·빈 환경·소스별 실패·연결 목록에 없는 환경의 스냅샷·40개 대상을 포함한다. 런타임 오류와 페이지 가로 넘침은 관찰되지 않았다. 사용자 수행 속도·오류율을 측정한 사용성 실험은 하지 않았다.

타입 검사, lint/디자인 규칙, 일반 빌드와 데모 빌드를 확인했다. React Doctor의 이번 변경에 대한 신규 진단은 오류0/경고0이다. 개요 시안과 비교 바는 개발 서버에서만 활성화된다. 업타임의 선택한 그리드·카드 기능은 프로덕션 빌드에도 포함되며 브라우저에서도 확인했다.

## 조사 근거

- [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/): 화면이 답할 질문과 전체에서 세부로 이어지는 흐름을 참고했다. 새 개요 A는 사용자가 명시한 전체 상태 파악이라는 목적에 따른 설계 판단이다.
- [IBM Carbon data table usage](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/components/data-table/usage.mdx): 열 비교와 보충 정보의 확장·상세 패널·전용 페이지 패턴을 참고했다.
- UI UX Pro Max 검색에서는 데이터 중심 대시보드와 상태 라벨·간격 가이드만 적합한 범위에서 사용했다. 정보 위계·장애 시간 구간·React 반응형 표에 대한 직접 적합 결과는 없었으므로 이를 스킬의 검증된 추천이라고 표현하지 않는다.

업타임 상세의 일별 가용성·응답 추이·장애 이력과 전역 셸 구조는 다음 별도 비교 단위다. 현재 시안으로 해당 재설계까지 완료한 것으로 보지 않는다. 업타임의 선택한 기능만 운영 코드로 분리할 수 있고, 아직 선택되지 않은 개요 시안과 전환 바는 이 탐색 브랜치에 보존한다. 현재 main에 병합하거나 배포하지 않았다.
