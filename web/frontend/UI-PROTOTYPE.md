# 개요·업타임 정보 구조 비교 시안

이 브랜치는 화면의 정보 목적과 구조를 비교하기 위한 임시 시안이다. 실서비스 구현으로 바로 병합하지 않는다.

## 실행

`web/frontend`에서 `pnpm dev:ui-prototype`을 실행한다. 기존 데모 데이터를 사용하며 서버나 계정은 필요 없다.

- 개요: <http://127.0.0.1:5186/?variant=A>
- 업타임 목록: <http://127.0.0.1:5186/uptime?variant=A>
- 하단 비교 바의 화살표 또는 키보드 좌우로 `current → A → B → C`를 전환한다. 입력창에서는 방향키로 시안을 바꾸지 않는다.
- URL의 `variant` 값은 새로고침 후에도 유지된다. 비교 바에서 개요와 업타임을 오갈 수 있다.
- 데모 시나리오 메뉴로 정상·장애 등 데이터 상황을 바꿀 수 있다. 시안은 기존 조회 흐름을 공유한다.

## 비교하는 질문

현재 카드나 배치를 유지할 이유부터 다시 검토한다. 어떤 화면이 많은 데이터를 넣는가보다, 사용자가 어떤 정보를 비교하고 무엇을 다음에 조사하는지 확인한다.

| 안 | 개요의 중심 | 업타임 목록의 중심 |
|---|---|---|
| current | 현재 배포 화면 | 현재 배포 화면 |
| A | 지금 조사할 신호와 해당 이력 | 상태 필터와 정렬 가능한 대상 비교 표 |
| B | 환경별 수신·서비스 상태의 범위 비교 | 대상 목록과 선택한 대상의 빠른 확인 패널 |
| C | 장애 시간 구간과 선택한 기록 | 환경·직접 체크별 접을 수 있는 그룹 |

## 현재 추천과 한계

- **개요 A를 기본 방향으로 추천한다.** 조사할 대상에 상태·출처·관련 장애 시작/지속 정보를 모아 놓는다. B의 범위 비교와 C의 시간 구간은 별도 목적의 보조 보기 후보로 둔다.
- **업타임 A를 기본 비교 화면으로 추천한다.** 여러 대상의 상태·주소·마지막 확인을 같은 열에서 비교한다. B의 빠른 확인 패널은 선택 조사에 필요한 부분만 가져올 수 있다. C는 환경 단위로 조사할 때 유용하다.
- 같은 40개 대상(장애 4개)의 1440×900 화면에서, 비교 바 위에 완전히 보이는 대상은 current 9개/장애 1개, A 6개/장애 4개, B 6개/장애 4개, C 6개/장애 1개였다. **A/B에는 상태 우선 정렬의 효과가 섞여 있다.** 표 자체의 우월성이나 사람의 탐지 속도를 입증하는 수치가 아니다.
- 375px에서는 A 표의 가로 이동이 필요하고 B의 빠른 확인 패널은 목록 아래에 놓인다. 실서비스 구현에서는 모바일의 핵심 필드 우선 행과 상세 확장을 별도 검증해야 한다.
- C의 그룹 순서는 출처 순서다. 다른 환경의 장애를 찾으려면 스크롤이 필요하며 헤더는 정상/장애 수만 요약한다. 접힌 상태의 수집 지연·대기·정지 표현은 후속 설계 항목이다.
- 개요 C는 최근 7일 중 최신 6개 기록만 사용한다. 빈 구간의 정상 여부나 전체 장애 건수를 뜻하지 않는다. 짧은 장애는 긴 시간축에서 매우 작아진다.
- Collector 수신 상태와 서비스 가용성을 구분한다. 목록에 없는 과거 추이·장애 시작·영향도·SLO를 만들어 표시하지 않는다.

## 검증 범위

현재안과 세 대안에 같은 정상·장애·빈 상태·부분 조회 실패·40개 대상 데이터를 넣어 1440/375px 및 대표 다크 테마를 관찰했다(88개 화면). 런타임 오류와 페이지 가로 넘침은 관찰되지 않았다. 필터·검색·정렬·선택·그룹 접기·시간 범위·비교 바·URL 유지도 브라우저에서 확인했다. 내부 표 가로 스크롤과 모바일 조사 비용은 위 한계에 포함된다. 사용자 수행 속도·오류율을 측정한 사용성 실험은 하지 않았다.

타입 검사, lint/디자인 규칙, 일반 빌드와 데모 빌드를 확인했다. 시안과 비교 바는 개발 서버에서만 활성화되며 프로덕션 빌드에서는 기존 화면이 열린다.

## 조사 근거

- [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/): 화면이 답할 질문과 전체에서 세부로 이어지는 흐름을 참고했다. 개요 A 추천은 이 원칙과 EveryUp 데이터에 대한 설계 판단이다.
- [IBM Carbon data table usage](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/components/data-table/usage.mdx): 열 비교와 보충 정보의 확장·상세 패널·전용 페이지 패턴을 참고했다.
- UI UX Pro Max 검색에서는 데이터 중심 대시보드와 상태 라벨·간격 가이드만 적합한 범위에서 사용했다. 정보 위계·장애 시간 구간·React 반응형 표에 대한 직접 적합 결과는 없었으므로 이를 스킬의 검증된 추천이라고 표현하지 않는다.

업타임 상세의 일별 가용성·응답 추이·장애 이력과 전역 셸 구조는 다음 별도 비교 단위다. 현재 시안으로 해당 재설계까지 완료한 것으로 보지 않는다. 선택한 구조는 실제 운영 기능과 접근성·반응형 요구를 반영해 다시 구현하고, 임시 시안과 전환 바는 이 탐색 브랜치에 보존한다.
