# 인프라 메뉴 UI·UX 점검 결과

작성일: 2026-11-11 · 기준: [점검 계획](infra-menu-ux-evaluation-plan.md) · HEAD `4594fe8b` (제품 코드 변경 없음) · 데모 `http://127.0.0.1:5207/everyup/demo/` · Chromium(Playwright)

계획의 전체 채점(4개 환경 × 평가 단위별 점수) 대신, 필요하다고 판단한 항목만 확인한 **약식 점검**이다. 점수는 매기지 않고 심각도(S1~S4)만 붙였다. 데스크톱 1440·모바일 390, 라이트·다크에서 목록·상세를 캡처하고 axe를 돌렸으며, 상태 처리는 소스로 확인했다. 증거는 [`infra-menu-ux-evaluation-evidence/`](infra-menu-ux-evaluation-evidence/)에 있다.

## 1. 요약

- 목록·상세의 기본 흐름(서버 선택 → 상세 → 기간 변경 → 복귀)과 빈 목록, 연결 대화상자는 막힘 없이 동작했다. 가로 넘침은 4개 환경 모두 없었다.
- **가장 큰 문제는 상세의 메트릭 조회 실패와 수신 전 상태다.** 오류를 `null`로 삼켜서 게이지는 사라지고 "인프라 추세" 제목만 남는다(I-01).
- **데모에서는 모든 서버의 상세 값이 똑같다.** 목록에서 메모리 84.6%였던 db-primary-01이 상세에서는 73%로 나온다(I-02).
- **같은 값이 화면마다 다른 정밀도로 보인다.** 목록 67.4%, 게이지 67%, 차트 머리 67.0%(I-04). 게이지와 차트가 같은 값을 두 번 보여 주는 구조 문제(§3 대안 A)와도 이어진다.

## 3. UI 구성 대안

### 대안 A. 상세: 게이지 줄을 없애고 차트 머리에 현재 값을 크게

지금 상세는 게이지 4개(현재 값 + sparkline/막대)와 추이 차트 4개(머리에 현재·평균·최대)가 같은 지표를 두 번 보여 준다. 게이지의 sparkline은 아래 차트의 축소판이고 기간도 다르다(I-09).

- **대안:** 게이지 줄을 없애고, 2×2 차트 머리의 "현재" 값을 크게(지금 게이지 크기로) 보여 준다. 용량(11.7 GB / 16.0 GB, In/Out)은 머리 아래 보조 줄로 옮긴다. 위험 상태는 머리에 배지로 표시한다.
- **효과:** 상세가 약 170px 짧아지고 모바일에서 첫 차트가 첫 화면 근처로 올라온다(I-08). I-04·I-09·I-10이 함께 사라진다.
- **비용:** M. `InfraGauges`는 Docker 환경 상세에서도 쓰므로 두 화면을 같이 바꿔야 한다. 2×2와 ChartCard 규칙은 그대로 지킨다.
- **참고:** 다른 제품의 상세 구성은 이번 약식 점검에서 다시 확인하지 않았다. 채택을 검토할 때 시안과 함께 확인한다.

### 대안 B. 목록: 숫자 대신 사용률 막대 + 위험 순 정렬

- **대안:** 표 보기에서 CPU·메모리·디스크 셀을 "숫자 + 가는 막대"로 바꾸고, 기본 정렬을 "가장 높은 사용률" 내림차순으로 한다. 70% 이상은 주의 색, 85% 이상은 위험 색으로 두 단계를 둔다. 마지막 수집 시각 열을 추가한다.
- **효과:** 서버가 많아져도 위험 서버가 위로 모이고, 85% 직전 값도 눈에 띈다(I-07).
- **비용:** M. 70% 주의 단계는 알림 임계값과 별개의 표시 기준이므로, 알림 점검 때 정할 임계값 설정과 겹치지 않게 해야 한다. 카드 보기도 같은 막대를 쓸지 정해야 한다.
- **참고:** 1차 점검의 비교 대상(Beszel `systems-table`, Checkmate Infrastructure)에서 셀 안 막대를 쓰는지는 시안 단계에서 다시 확인한다.

### 대안 C (권장하지 않음). 목록 카드에 sparkline

카드마다 최근 추이를 넣는 방안도 검토했다. 그러나 목록 API에 이력이 없어 서버당 추가 요청이 필요하고, 로그 메뉴에서 작은 추이 그래프를 읽기 어렵다는 결과(로그 I-06)가 이미 나왔다. 대안 B가 같은 목적을 더 싸게 이룬다.
