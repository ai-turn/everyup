# 모니터링 설정

Docker Collector의 수집 상태를 확인하거나 수집 범위를 넓힐 수 있습니다.
Docker 밖의 앱과 서버는 [OpenTelemetry로 직접 연결](#direct-otel)하세요. Docker Collector 설치 없이도 연결할 수 있습니다.
Docker Collector를 처음 설치하려면 [Quick Start](./quickstart#docker)를 참고하세요.

## Docker Collector 설정 가이드

Docker Collector가 있는 서버의 **개요** 탭 맨 위에 **Docker Collector 설정 가이드**가 있습니다. 이 가이드가
Docker Collector 설치, 기본 수집, API 요청 자동 수집을 순서대로 진단합니다. Java·Node.js 컨테이너가 발견되면
같은 가이드에서 선택 기능인 헤더·바디 상세 수집 설정으로 바로 이어집니다.

## 수집 상태 읽는 법

설정 가이드에서는 Docker Collector의 최근 통신 여부와 수집 범위 적용 여부를 따로 확인할 수 있습니다.
Docker Collector가 한 번도 보고하지 않은 서버는 서버 목록과 가이드 모두 **설치 대기**로 표시합니다. 설치한 뒤의 연결 여부는
최근 2분 안에 Web과 통신했는지로 판단합니다. 설정 적용 여부는 Docker Collector가 보고한
설정이 요청한 수집 범위와 일치하는지로 판단합니다.

로그, 트레이스, 메트릭, 인프라는 데이터가 처음 들어온 시각과 마지막으로 들어온 시각을 기록하며,
화면은 이 값을 5초마다 갱신합니다.
대상을 등록하거나 전송 권한을 추가한 것만으로 데이터가 수신되지는 않습니다.
앱이나 Collector에 전송 설정을 적용한 뒤 **데이터 수신 확인**을 보세요.

| 표시 | 뜻 |
| --- | --- |
| **수신 대기** | 아직 한 번도 받지 않았습니다 |
| **수집 지연** | 마지막으로 받은 지 10분이 넘었습니다 |

이 표시는 수신 이력을 기준으로 판단하므로, 현재 연결이 정상이라고 보장하지는 않습니다.

::: tip 통신은 되는데 계속 대기 상태라면
구버전 Collector는 Web과 통신하더라도 설정 적용 확인이 대기 상태로 남을 수 있습니다. 최신 설치
명령으로 Collector를 업데이트하세요.
:::

## Docker Collector에 기능 연결

Docker Collector가 있는 서버의 **개요** 탭에서, 설정 가이드의 **인프라 연결**·**메트릭 연결** 같은 버튼으로
아직 선택하지 않은 기능을 연결하세요. 대화 상자에서 **적용 명령 받기**를 누르면 새 적용 명령이 나옵니다.
ID·키·수집 이력은 유지됩니다. 이 명령을 그 호스트에서 실행하면 선택한 기능이 그 서버의 Docker Collector 전체에
적용되고, 앱은 다시 시작하지 않아도 됩니다.

서버 머리말의 **설치 명령**은 Docker Collector를 설치하기 전에만 보입니다. 설치한 뒤에 다시 설치하려면 머리말의
더보기(⋮) 메뉴에서 **다시 설치**를 누르세요.

서버의 로그·API 요청·메트릭·인프라 탭에 있는 연결 버튼(**로그 연결**, **API 요청 연결** 등)은 직접 연결만 다룹니다.
새 앱을 연결하거나, 이 서버에 이미 연결한 앱에 데이터를 더할 수 있습니다. 연결을 마치면 그 앱의 페이지로 이동합니다.

## 호스트 지표 출처 {#host-metrics-source}

서버 하나의 호스트 지표(CPU·메모리·디스크)는 한 곳에서만 수집합니다. Docker Collector의 인프라 기능과
OpenTelemetry Collector(**인프라 연결**)가 같은 호스트를 수집하게 되는 경우, EveryUp은 둘 중 하나를 고르게 합니다.
고르지 않으면 연결하지 않습니다.

| 상황 | 고르는 곳 |
| --- | --- |
| OpenTelemetry Collector로 인프라를 연결한 서버에 Docker Collector 설치 | 설치 창의 **호스트 지표 출처** (수집 범위가 **기본**이면 묻지 않습니다) |
| Docker Collector가 호스트 지표를 수집하는 서버에서 **인프라 연결** | 인프라 연결 대화 상자 |
| OpenTelemetry Collector로 인프라를 연결한 서버에서 Docker Collector에 인프라 추가 | 설정 가이드의 기능 연결 대화 상자 |
| 두 서버 합치기 | **다른 서버 합치기** 대화 상자 |

- **Docker Collector**를 남기면 OpenTelemetry Collector 인프라 리소스의 연결을 중지합니다. 이미 수집한 기록은 남습니다.
- **OpenTelemetry Collector**를 남기면 Docker Collector의 수집에서 인프라를 뺍니다. Docker Collector가 이미
  설치되어 있다면 화면에 나오는 적용 명령을 그 호스트에서 실행하세요.

## 같은 호스트의 서버 합치기 {#same-host-merge}

Docker Collector를 설치한 호스트를 서버로도 따로 등록했다면, 같은 호스트가 서버 두 개로 나뉘어 보입니다.
이전 버전에서 Docker 환경으로 연결한 호스트는 업그레이드 뒤 같은 이름의 서버가 됩니다. 같은 이름의 서버가
이미 있으면 새 서버의 이름 뒤에 ` (2)`가 붙습니다. EveryUp은 서버를 자동으로 합치지 않습니다.

서버 이름은 전체에서 하나입니다(대소문자와 앞뒤 공백은 구분하지 않습니다). 이전 버전의 그룹은 없어졌고, 그룹이 달라 이름이
같았던 서버는 업그레이드할 때 합쳐지지 않고 이름이 바뀝니다. 가장 먼저 만든 서버가 이름을 그대로 쓰고, 나머지는 이름 뒤에
옛 그룹 이름이 붙습니다(예: `api-server (Staging)`). 그 이름도 이미 있으면 ` (2)`가 더 붙습니다.

이름이 같은 두 서버가 있으면 **개요**에 **같은 호스트인가요?**가 나타납니다(` (2)` 같은 접미사는 무시합니다).
**합치기**를 누르면 직접 등록한 서버가 열리고, 합칠 서버가 선택된 **다른 서버 합치기** 대화 상자가 열립니다.
다른 호스트라면 **아님**을 누르세요. 이 답은 모든 사용자에게 적용되므로 다시 묻지 않습니다.
이름이 달라도 서버 머리말의 **서버 설정**(⚙)에서 **다른 서버 합치기**를 눌러 직접 합칠 수 있습니다.

- 선택한 서버의 대상(컨테이너와 Docker Collector 포함)은 모두 지금 서버로 옮겨지고, 선택한 서버는 삭제됩니다.
  삭제된 서버의 주소로 들어오면 남은 서버로 이동합니다.
- Docker Collector의 ID와 API Key는 바뀌지 않으므로 호스트에서 다시 설치하지 않아도 됩니다.
- 서버 하나에는 Docker Collector를 하나만 둘 수 있습니다. 두 서버 모두 Docker Collector가 있으면 합칠 수 없습니다.
- 두 서버가 모두 호스트 지표를 수집하면 [호스트 지표 출처](#host-metrics-source)를 하나 고릅니다.

## OpenTelemetry로 직접 연결 {#direct-otel}

Docker 밖에서 실행되는 앱은 로그·트레이스·메트릭을 OpenTelemetry로 직접 보냅니다.
서버 자원은 표준 OpenTelemetry Collector로 보냅니다. 연결할 데이터에 따라 다음 경로를 선택하세요.

| 데이터 | 대시보드에서 여는 경로 |
| --- | --- |
| 로그 | **서버** → 서버 → **로그** 탭 → **로그 연결** |
| API 요청·트레이스 | **서버** → 서버 → **API 요청** 탭 → **API 요청 연결** |
| 앱 메트릭 | **서버** → 서버 → **메트릭** 탭 → **메트릭 연결** |
| 서버 자원 | **서버** → 서버 → **인프라** 탭 → **인프라 연결** |

연결은 그 데이터가 보일 자리에서 시작합니다. 서버의 **개요** 탭에 있는 같은 이름의 버튼을 눌러도 그 탭으로 옮기면서
같은 대화 상자가 열립니다. 트레이스는 따로 연결하지 않습니다. **API 요청**을 연결하면 앱 페이지의 **트레이스** 탭에도
데이터가 들어옵니다.

이미 연결한 앱에 다른 데이터를 더하려면 그 앱의 페이지에서 **연결 전** 탭을 열거나, 연결 줄의 **연결 추가**를 누르세요.
받지 않는 데이터가 둘 이상이면 **연결 추가**가 고를 수 있는 메뉴를 엽니다. 연결 대화 상자의 **기존 앱**에서는 이 서버의
앱만 고를 수 있습니다. 다른 서버의 앱이라면 그 앱 페이지에서 **다른 서버로 옮기기**로 이 서버로 옮긴 뒤 연결하세요.

모든 연결 대화 상자는 첫 줄의 **적용 범위**에 무엇에 적용되는지와 앱이나 서버에서 할 일을 적습니다. 이 서버에
Docker Collector가 있다면, 컨테이너로 도는 앱은 그 Docker Collector로 연결하세요. 대화 상자도 이를 안내합니다.
같은 호스트의 Docker Collector가 다른 서버에 설치되어 있다면 먼저 [두 서버를 합치세요](#same-host-merge).

앱을 연결하면 데이터 전송 주소와 API Key를 확인할 수 있습니다.
OpenTelemetry를 처음 설정한다면 Java·Node.js·Go 안내에 따라 SDK와 exporter를 연결하세요.
환경변수만 추가해서는 데이터가 전송되지 않습니다. 직접 OTLP 로그를 보내려면 로깅 라이브러리의
OTel bridge나 appender도 필요합니다.

이미 OpenTelemetry를 사용하고 있고 기존 전송 대상도 유지하려면 OpenTelemetry Collector에 EveryUp용 exporter를
추가하세요. 앱의 공통 OTLP 주소를 바꾸면 기존 전송 대상이 대체될 수 있습니다.

이미 연결한 앱에 데이터를 더하면 기존 ID와 API Key를 유지한 채 필요한
데이터 권한만 추가합니다. 이후 앱이나 Collector에서 해당 데이터 유형의 전송을 설정하고 재시작·재배포하세요.
요청이나 로그를 발생시키고, 메트릭은 수집 주기가 지난 뒤 **데이터 수신 확인**에서 수신 여부를 확인하세요.

## 메트릭 탐색하기

서버의 **메트릭** 탭에서 앱을 열면 앱 페이지의 **메트릭** 탭에서 메트릭을 이름순으로 12개씩 볼 수 있습니다. 더 보려면 **메트릭 12개 더 보기**를 누르세요.
Docker Collector가 수집한 메트릭은 서버의 **컨테이너** 탭에서 컨테이너를 열고 **메트릭** 탭에서 확인합니다.

메트릭 제목을 눌러 단독 보기를 열면 다음 조건을 조절할 수 있습니다.

- **Attribute 필터**: key, 값, 값 타입을 입력하고 **필터 적용**을 누릅니다. 최대 8개 조건을 모두 만족하는 시리즈를 조회합니다. 문자열 `"1"`과 숫자 `1`은 서로 다릅니다.
- **시리즈 선택**: Attribute 조합으로 검색하고 최대 6개를 선택합니다. 목록은 처음 200개까지 표시하므로, 원하는 시리즈가 없으면 Attribute 필터를 좁히세요. **기본 선택**은 현재 조건의 첫 6개를 선택합니다.
- **초당 증가량**: sum의 단독 보기에서 선택합니다. 단조 증가하는 sum에 한해, delta는 값을 수집 구간의 초로 나누고 cumulative는 같은 스트림의 연속된 두 값의 차이를 시간 차이로 나눕니다.

기간·메트릭 검색·단독 보기·필터·시리즈 선택·값 표시 방식은 URL에 남습니다. 기간은 접속 시점을 기준으로 다시 계산합니다.
histogram의 **선택한 시리즈의 기간 분포**에는 차트와 같은 필터·시리즈·조회 기간을 적용합니다.
선은 각 수신 포인트의 평균이고, 분포의 p50·p95·p99는 저장된 bucket에서 계산합니다.
차트 요약의 평균은 표시된 포인트의 평균입니다.

초당 증가량에는 SDK가 보내는 누적 방식, 단조 증가 여부, 누적 시작 시각이 필요합니다.
여러 인스턴스는 `service.instance.id` 등으로 서로 다른 resource를 보내야 합니다.
메타데이터 보존 기능을 적용하기 전에 저장한 sum은 원값으로 확인하세요. 새 메타데이터는 이후 수신분부터 저장하며,
누적 시작 정보가 없거나 재시작·겹침이 감지된 포인트는 증가량을 계산하지 않습니다. 알림 임계값은 원값 기준입니다.
데이터 해석의 기준은 [OpenTelemetry 메트릭 모델](https://opentelemetry.io/docs/specs/otel/metrics/data-model/)입니다.

차트는 선택한 시리즈의 최근 5,000개 포인트까지 표시합니다. 한도를 넘으면 기간이나 Attribute 필터를 좁히세요.
분포는 선택한 시리즈의 전체 조회 기간을 사용하지만, 50,000개 포인트를 넘으면 수치를 표시하지 않고 범위를 줄이라는 안내를 보여 줍니다.

## 헤더·바디 상세 수집

적용할 Java·Node.js 컨테이너를 직접 고른 뒤 **변경 사항 확인**으로 재시작 범위를 확인합니다.
서버에서 `everyup-otel plan`으로 실제 Compose를 검증하고 적용 명령을 실행하면, 실행할 때마다
적용·검증·복구 결과가 Web에 표시됩니다. 자세한 내용은
[헤더·바디 상세 수집](./otel-instrumentation)을 참고하세요.
