# 모니터링 설정

Docker 환경의 수집 상태를 확인하거나 수집 범위를 넓힐 수 있습니다.
Docker 밖의 앱과 서버는 [OpenTelemetry로 직접 연결](#direct-otel)하세요. Docker Collector 설치 없이도 연결할 수 있습니다.
첫 Docker 환경을 연결하려면 [Quick Start](./quickstart#docker)를 참고하세요.

## 모니터링 설정 가이드

**Docker 환경** 화면에서 환경을 열면 나오는 **모니터링 설정 가이드**가 Collector 연결, 기본 수집, API 요청 자동 수집을
순서대로 진단합니다. Java·Node.js 서비스가 발견되면 같은 가이드에서 선택 기능인
헤더·바디 상세 수집 설정으로 바로 이어집니다.

## 수집 상태 읽는 법

설정 가이드에서는 Collector의 최근 통신 여부와 수집 범위 적용 여부를 따로 확인할 수 있습니다.
연결 여부는 최근 2분 안에 Web과 통신했는지로 판단합니다. 설정 적용 여부는 Collector가 보고한
설정이 요청한 수집 범위와 일치하는지로 판단합니다.

로그, 트레이스, 메트릭, 인프라는 데이터가 처음 들어온 시각과 마지막으로 들어온 시각을 기록하며,
화면은 이 값을 5초마다 갱신합니다.
대상을 등록하거나 전송 권한을 추가한 것만으로 데이터가 수신되지는 않습니다.
앱이나 Collector에 전송 설정을 적용한 뒤 **데이터 수신 확인**을 보세요.

| 표시 | 뜻 |
| --- | --- |
| **수신 대기** | 아직 한 번도 받지 않았습니다 |
| **수집 지연** | 마지막으로 받은 지 10분이 넘었습니다 |

이 표시는 수신 이력을 기준으로 판단하므로, 현재 연결이 정상이라고 보장하지는 않습니다.

::: tip 통신은 되는데 계속 대기 상태라면
구버전 Collector는 Web과 통신하더라도 설정 적용 확인이 대기 상태로 남을 수 있습니다. 최신 설치
명령으로 Collector를 업데이트하세요.
:::

## 기존 환경에 기능 추가

**Docker 환경** 화면에서 환경을 열고, 모니터링 설정 가이드의 **로그 추가**·**메트릭 추가** 같은 버튼으로
아직 선택하지 않은 기능을 추가하세요. ID·키·그룹·수집 이력은 유지되고, 새 적용 명령이 발급됩니다.
이 명령을 해당 서버에서 실행하면 선택한 기능이 Docker 환경 전체에 적용됩니다.

로그·API 요청·메트릭·인프라 화면의 연결 버튼(**로그 연결**, **API 연결** 등)은 직접 연결만 다룹니다.
등록된 직접 연결 대상을 이어 쓰거나 새 대상을 연결할 수 있습니다. 이미 설정된 대상을 고르면 수신 기록을
확인한 뒤 해당 데이터 화면으로 이동합니다.

## OpenTelemetry로 직접 연결 {#direct-otel}

Docker 밖에서 실행되는 앱은 로그·트레이스·메트릭을 OpenTelemetry로 직접 보냅니다.
서버 자원은 표준 OpenTelemetry Collector로 보냅니다. 연결할 데이터에 따라 다음 경로를 선택하세요.

| 데이터 | 대시보드에서 여는 경로 |
| --- | --- |
| 로그 | **로그 → 로그 연결 → OpenTelemetry로 직접 연결** |
| API 요청·트레이스 | **API 요청 → API 연결 → OpenTelemetry로 직접 연결** |
| 앱 메트릭 | **메트릭 → 메트릭 연결 → OpenTelemetry로 직접 연결** |
| 서버 자원 | **인프라 → 인프라 연결** |

직접 연결 화면에서 서비스를 추가하면 데이터 전송 주소와 API Key를 확인할 수 있습니다.
OpenTelemetry를 처음 설정한다면 Java·Node.js·Go 안내에 따라 SDK와 exporter를 연결하세요.
환경변수만 추가해서는 데이터가 전송되지 않습니다. 직접 OTLP 로그를 보내려면 로깅 라이브러리의
OTel bridge나 appender도 필요합니다.

이미 OpenTelemetry를 사용하고 있고 기존 전송 대상도 유지하려면 Collector에 EveryUp용 exporter를
추가하세요. 앱의 공통 OTLP 주소를 바꾸면 기존 전송 대상이 대체될 수 있습니다.

직접 OpenTelemetry로 연결한 서비스에 기능을 추가하면 기존 ID와 API Key를 유지한 채 필요한
데이터 권한만 추가합니다. 이후 앱이나 Collector에서 해당 데이터 유형의 전송을 설정하고 재시작·재배포하세요.
요청이나 로그를 발생시키고, 메트릭은 수집 주기가 지난 뒤 **데이터 수신 확인**에서 수신 여부를 확인하세요.

## 메트릭 탐색하기

**메트릭**에서 서비스를 열면 메트릭을 이름순으로 12개씩 볼 수 있습니다. 더 보려면 **메트릭 12개 더 보기**를 누르세요.
Docker Collector가 수집한 메트릭은 해당 **Docker 환경**의 서비스 상세에서 확인합니다.

메트릭 제목을 눌러 단독 보기를 열면 다음 조건을 조절할 수 있습니다.

- **Attribute 필터**: key, 값, 값 타입을 입력하고 **필터 적용**을 누릅니다. 최대 8개 조건을 모두 만족하는 시리즈를 조회합니다. 문자열 `"1"`과 숫자 `1`은 서로 다릅니다.
- **시리즈 선택**: Attribute 조합으로 검색하고 최대 6개를 선택합니다. 목록은 처음 200개까지 표시하므로, 원하는 시리즈가 없으면 Attribute 필터를 좁히세요. **기본 선택**은 현재 조건의 첫 6개를 선택합니다.
- **초당 증가량**: sum의 단독 보기에서 선택합니다. 단조 증가하는 sum에 한해, delta는 값을 수집 구간의 초로 나누고 cumulative는 같은 스트림의 연속된 두 값의 차이를 시간 차이로 나눕니다.

기간·메트릭 검색·단독 보기·필터·시리즈 선택·값 표시 방식은 URL에 남습니다. 기간은 접속 시점을 기준으로 다시 계산합니다.
histogram의 **선택한 시리즈의 기간 분포**에는 차트와 같은 필터·시리즈·조회 기간을 적용합니다.
선은 각 수신 포인트의 평균이고, 분포의 p50·p95·p99는 저장된 bucket에서 계산합니다.
차트 요약의 평균은 표시된 포인트의 평균입니다.

초당 증가량에는 SDK가 보내는 누적 방식, 단조 증가 여부, 누적 시작 시각이 필요합니다.
여러 인스턴스는 `service.instance.id` 등으로 서로 다른 resource를 보내야 합니다.
메타데이터 보존 기능을 적용하기 전에 저장한 sum은 원값으로 확인하세요. 새 메타데이터는 이후 수신분부터 저장하며,
누적 시작 정보가 없거나 재시작·겹침이 감지된 포인트는 증가량을 계산하지 않습니다. 알림 임계값은 원값 기준입니다.
데이터 해석의 기준은 [OpenTelemetry 메트릭 모델](https://opentelemetry.io/docs/specs/otel/metrics/data-model/)입니다.

차트는 선택한 시리즈의 최근 5,000개 포인트까지 표시합니다. 한도를 넘으면 기간이나 Attribute 필터를 좁히세요.
분포는 선택한 시리즈의 전체 조회 기간을 사용하지만, 50,000개 포인트를 넘으면 수치를 표시하지 않고 범위를 줄이라는 안내를 보여 줍니다.

## 그룹으로 묶기

따로 등록한 대상을 함께 보려면 사이드바 **모아 보기**의 **그룹** 화면에서 **추가**를 눌러 그룹을 만드세요.
그룹을 만들면 그룹 화면이 열립니다. **대상 추가**를 누르고 Docker 환경, 업타임 모니터, 직접 연결한 서비스, 인프라 Collector를 여러 개 골라 **추가**하세요.
다른 그룹에 있던 대상을 고르면 이 그룹으로 옮겨집니다. 그룹에서 빼려면 대상 행의 **빼기**를 누르세요. 대상은 지워지지 않고 미분류로 돌아갑니다.
Docker 환경의 하위 서비스와 데이터는 환경의 그룹 배정을 따릅니다.
그룹 목록에서는 그룹마다 장애·확인 필요·정상 대상 수를 요약해 보여 주고, 그룹 화면은 장애가 있는 대상을 먼저 보여줍니다. 그룹을 삭제해도 배정된 대상은 삭제되지 않습니다.

## 헤더·바디 상세 수집

적용할 Java·Node.js 서비스를 직접 고른 뒤 **변경 사항 확인**으로 재시작 범위를 확인합니다.
서버에서 `everyup-otel plan`으로 실제 Compose를 검증하고 적용 명령을 실행하면, 실행할 때마다
적용·검증·복구 결과가 Web에 표시됩니다. 자세한 내용은
[헤더·바디 상세 수집](./otel-instrumentation)을 참고하세요.
