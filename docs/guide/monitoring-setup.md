# 모니터링 설정

[Quick Start](./quickstart)로 첫 Docker 환경을 연결한 뒤, 수집 상태를 진단하거나 수집 범위를
넓힐 때 쓰는 화면을 설명합니다.

## 모니터링 설정 가이드

**Docker 환경** 화면의 **모니터링 설정 가이드**가 Collector 연결, 기본 수집, API 요청 자동 수집을
순서대로 진단합니다. Java·Node.js 서비스가 발견되면 같은 가이드에서 선택 기능인
헤더·바디 상세 수집까지 바로 이어서 설정할 수 있습니다.

## 수집 상태 읽는 법

설정 가이드는 두 가지를 따로 보여줍니다. 하나는 Collector가 최근 2분 안에 Web과
통신했는지이고, 다른 하나는 요청한 수집 범위가 실제로 적용되었는지입니다.

로그, 트레이스, 메트릭, 인프라는 데이터가 처음 들어온 시각과 마지막으로 들어온 시각을 기록하며,
화면은 이 값을 5초마다 갱신합니다.

| 표시 | 뜻 |
| --- | --- |
| **수신 대기** | 아직 한 번도 받지 않았습니다 |
| **수집 지연** | 마지막으로 받은 지 10분이 지났습니다 |

이 표시는 수신 이력을 기준으로 판단하므로, 현재 연결이 정상이라고 보장하지는 않습니다.

::: tip 통신은 되는데 계속 대기 상태라면
구버전 Collector는 Web과 통신하더라도 설정 적용 확인이 대기 상태로 남을 수 있습니다. 최신 설치
명령으로 Collector를 업데이트하세요.
:::

## 기존 환경에 기능 추가

로그·API·메트릭·인프라 메뉴의 **연결** 버튼에서는 등록된 대상을 이어 쓰거나 새 대상을
연결할 수 있습니다. 기존 Docker 환경에 기능을 추가하면 ID·키·Project·수집 이력은
유지되고, 새 적용 명령이 발급됩니다. 이 명령을 해당 서버에서 실행하면 선택한 기능이
Docker 환경 전체에 적용됩니다.

각 메뉴의 연결 화면에서는 기존 대상을 고르거나 Docker 설치를 시작할 수 있습니다. 이미 설정된
대상을 고르면 수신 기록을 확인한 뒤 해당 데이터 화면으로 이동합니다.

## OpenTelemetry로 직접 연결

로그·API·메트릭은 앱을 OpenTelemetry로 직접 연결할 수 있고, 인프라는 표준 OpenTelemetry
Collector를 연결할 수 있습니다. 직접 연결 화면은 기존 OTel 사용 여부와 Java·Node.js·Go 환경에
맞춰 설정 적용, 재시작, 데이터 발생, 수신 확인 순서를 안내합니다.

직접 OpenTelemetry로 연결한 서비스에 기능을 추가하면 기존 ID와 API Key를 유지한 채 필요한
데이터 권한만 추가합니다. 이후 안내에 따라 앱 또는 Collector 설정을 갱신하고 데이터를 발생시켜
수신 여부를 확인하세요.

## 헤더·바디 상세 수집

적용할 Java·Node.js 서비스를 직접 고른 뒤 **변경 사항 확인**으로 재시작 범위를 확인합니다.
서버에서 `everyup-otel plan`으로 실제 Compose를 검증하고 적용 명령을 실행하면, 실행할 때마다
적용·검증·복구 결과가 Web에 표시됩니다. 자세한 내용은
[헤더·바디 상세 수집](./otel-instrumentation)을 참고하세요.
